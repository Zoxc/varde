| `kernel-compat` | `varde-kernel-compat`   | The facade between the app and the Varde kernel: the old kernel's public API, kept so the other crates build unchanged, its implementation gone (at the git tag `varde-kernel-legacy`). | `app`      | `varde-app`      | Owns app state (`Editor`, `Camera`, the mesh feed of what it asked `regen` for and the newest mesh and sketch lines answered, the sketch being edited (`SketchSession`: the tool, the selection, a drag session, the analyses, the value field) and the edits the sketch tools make, values typed read with `expr`, proposed through the document's solver lane (`Proposals`), the extrude being set up (`ExtrudeSession`, previewed as a regeneration draft, as the revolve's and the combine's, `CombineSession`), the measure tool's picks (`MeasureSession`, measured with each regeneration), what's hovered and selected in the model and its highlight (`ModelPick`), a body's opacity previewed while its slider is dragged, a delete waiting on the prompt (`Deleting`), recent files), handles the view's `Message`s, keys and its own messages from the lanes, dialogs and timers, sends file work to the IO lane, natively runs the MCP server's subscription and answers its tool calls from the open design (`mcp.rs`; on the web a no-op stand-in, `mcp_web.rs`), exposes `run()` (and `thumbnail_of`, the images a save's thumbnail is made of). Its `samples` example (`cargo run -p varde-app --example samples`) writes the sample designs of `examples/` with their thumbnails, rendered offscreen as a save would. |
| `binary`   | `varde`          | Native executable; calls `varde_app::run()`, or, given `mcp` as its first argument, runs the stdio relay to the app's MCP server instead (`src/mcp.rs`: `varde_mcp::relay` with the port and token `varde-io` reads from the user's files; no window, iced or wgpu). |
| `web`      | `varde-web`      | wasm build of the same app, built with trunk as one module that also runs the lanes' Web Workers (`serve_worker`); does nothing natively. Its `samples` feature (`varde-app/samples`) builds in the sample designs of `examples/`, listed on the start page; the GitHub Pages build turns it on with `data-cargo-features="samples"` on the page's `rel="rust"` link, `trunk serve` leaves it off (see `web-files.md`). |

## The web build

`trunk` builds one wasm module from `crates/web/index.html`: `varde-web`, a
`cdylib` that holds the app and the regeneration, solver and IO Web Workers'
sides, so the code they share is downloaded and compiled once. It exports
`start`, which wasm-bindgen runs as every instance starts and which runs the
app on the page only, and `serve_worker(role)`, which runs the lane the role
names (the `id` of the `WORKER` role, a `varde_lane::page::Role`, of `varde-regen`,
`varde-solve` and `varde-io`, which also gives its name in errors and its `serve`).
A worker is an instance of its own of that module, sharing none of the page's
memory: `varde_lane::page::Host::start` starts `crates/web/worker_loader.js`,
copied next to the page, as a module worker and posts it the page's compiled
`WebAssembly.Module`, the URL of wasm-bindgen's glue (found by the
`modulepreload` link trunk puts in the page, as the name holds a hash) and the
role. The loader imports the glue, instantiates the module and calls
`serve_worker`; whatever fails there it rethrows from a task of its own, so the
page's `Worker.onerror` hears of it rather than wait for answers that never
come. Each instance has its own copy of the module's data, the embedded fonts
and sample designs among them.

## Look and assets

The look follows `notes/ui-mock/` (`welcome.html`, `model.html`,
`sketch.html`). The welcome screen has both of `welcome.html`'s layouts:
natively the grey column with the logo, Start and the help beside the
recovered and recent designs, on the web (no recent files) the page with
a header bar over the cards of what's in browser storage. The logo is
`assets/logo.svg`; the checked-in `assets/logo.ico` is embedded as the
Windows executable icon by `crates/binary/build.rs`, which has the
command to regenerate it.

Natively text uses the system's fonts. The web has none, so `crates/web`
loads Fira Sans SemiBold and Fira Mono from `crates/web/fonts` (OFL, its
license beside them) beside iced's Fira Sans Regular, and maps the generic
sans-serif and monospace families to them (`src/lib.rs`, `load_fonts`).

The tools' icons (`crates/view/src/icons.rs`) are the default set of
`notes/ui-mock-icons.html`: its "outline with accents, line only" drawings
in its "Distinct, purple constraints" colours with the softer accent. The
drawings keep the mock's classes: unclassed elements are the tool's own
geometry, `a` its accent strokes, `af` accent dots drawn hollow (their
insides masked out of what's under them, rather than filled with the
panel colour as in the mock), `r` reference geometry. `Icon::category`
files each tool (sketch, modify, constraint, dimension, solid,
construction), and `theme::IconColors` derives each category's line,
accent and reference colours for both palettes as the mock does. `icons::icon`
stacks the three layers, each an SVG tinted through `svg::Style`;
`icons::tinted` and `icons::button_icon` draw all of an icon in one
colour, as the constraint glyphs in the viewport and the panel tabs do.
Other icons (file, undo, eye, alert, ...) are from `notes/ui-mock/mock.js` and drawn
in the text colour, or tinted where they're used. The operation panel's
choices (`Icon::Rv*`, `Ex*`, `Bo*`, `Lp*`, `Cp*`, the model mock's `CHOICE_ICONS`) are
drawn as the tools' are, in the Solid category's colours; what's picked
(`SeRegion`, `SeAxis`, its `SELECTION_ICONS`) in the sketch's and
construction's; the options' (`TkFlip`, `TkKeep`) in one colour. The
mock's `fl` class, a light fill, is kept: the element filled in its
layer's colour at 0.18 opacity. The tools the icon mock lacks (the offset constraint,
Convert, Handles, Comb) keep their own one-layer drawings, in their
category's line colour; so does the Body icon.
The tool rail's sets have category icons (`Icon::Cat*`), the mock's
`cat-*` drawings ("Line · Results"), in the same three layers and filed
under their set's category: Create with Solid, the sketch's Modify with
Modify, and so on; the mock's group turned for Constraints is turned per
element, as an icon is a list of empty tags.

## Roadmap by crate

- **kernel**: the old kernel is replaced by the facade in `kernel-compat`, so for now the app regenerates no geometry (every feature making a solid fails as not implemented) and its tests that need solids fail; the Varde kernel's primitives, extrude, revolve and tessellation come first, then its booleans, each wired into the facade as it lands.
- **sketch**: the shape tools' geometry (trim, offset, fillet).
- **document**: sketches on faces are in (`Plane::Face`, `Placement::on_plane`, `SetSketchPlane`), and regen places them (`Evaluation::placements`, on the wire), and the app sketches on them, changes a sketch's plane and asks for another for one whose face is gone; combines are in (`FeatureKind::Combine`, regen, and the session: `B`, bodies picked in the viewport or Objects, Keep tools); moves and mirrors are in the document and regen (`FeatureKind::Move`, `FeatureKind::Mirror`, `AxisRef`, `Plane`), and their UI (`M`, typed fields, the axis or plane picked and drawn); linear and circular patterns are in the document, regen and the UI (`FeatureKind::Pattern`, `PatternKind`; `P`, the mock's panels with Spacing, Total and Full 360°); aligns are in the document, regen and the UI (`FeatureKind::Align`, `PointRef`, `DirRef`, `AlignRefs`, the datums found on the wire; the rail's Align, points at the measure tool's snap dots, a panel in the style of the mock's Move); scales are in the document, regen and the UI (`FeatureKind::Scale`, `ScaleFactor`, `Ask::factor`, what's found on the wire; the rail's Scale, its point picked as an align's, Uniform, Per axis or Edge length, the edge measured with the model, a panel in the style of the mock's Move); splits are in the document, regen and the UI (`FeatureKind::Split`, `SplitTool`, `Side`, `Keep`, a new body made by the split, sketches on faces following into it; the rail's Split body, a plane, face, body, sketch regions or line picked, Keeps and Keep, a panel in the style of the mock's Combine and Mirror) on a kernel stand-in that fails as not implemented until the kernel's split is built; chamfers are in the document, regen and the UI (`FeatureKind::Chamfer`, `ChamferSize`, `MAX_BLEND_EDGES`, edges on one body, tangent chains grown by regen; `C`, edges picked and toggled in the viewport by the edge session the fillet shares, the mock's panel with Equal, Two distances and Distance and angle, Flip sides and Tangent chain) on a kernel stand-in failing as not implemented; fillets are in the document, regen and the UI (`FeatureKind::Fillet`, one radius, edges as a chamfer's, checked by the same `check_blend_edges_own` and `Document::check_blend_edges`; `F` and the rail's Modify set (not the toolbar: no room at 1280 px), the chamfer's edge session, the mock's panel with Edges, Radius and Tangent chain) on a kernel stand-in failing as not implemented; shells are in the document, regen and the UI (`FeatureKind::Shell`, `MAX_SHELL_FACES`, open faces on its body, inward or outward; the rail's Shell, faces picked and toggled in the viewport by the face session offset face shares and draft will, none for a closed one, the mock's panel with Remove, Thickness and Direction) on a kernel stand-in failing as not implemented; offset faces are in the document, regen and the UI (`FeatureKind::OffsetFace`, `MAX_OFFSET_FACES`, faces of one body moved out or in, tangent faces; the rail's Offset face, faces picked by the face session, the extrude's handle along the first face's normal and a typed distance, a panel in the style of the mock's shell panel) on a kernel stand-in failing as not implemented;
